# 两台爱快之间的 HY2 反向端口映射

本功能用于两台运行相应 NativeRouting 构建的 x86_64 爱快。客户端主动经现有 HY2 建立反向通道，外部访问者连接服务端的指定端口后，由客户端连接它本机或局域网中的目标服务。客户端可以位于 NAT 后，不需要公网入站端口。

两端都需要包含此功能的固件。原版爱快、现有未包含本功能的 NativeRouting 发布版，以及只导入普通 sing-box JSON 的手机客户端，不会因此建立反向通道。

## 配置示例

假设客户端爱快管理地址为 `192.168.62.1:80`，客户端局域网还有一台 `192.168.62.10:443` 的设备。可以在服务端为这台纯 HY2 设备启用“反向端口映射”，添加：

| 协议 | 服务端端口 | 客户端目标地址 | 客户端目标端口 | 访问方式 |
| --- | --- | --- | --- | --- |
| TCP | 18080 | 192.168.62.1 | 80 | `http://服务端公网IP:18080` |
| TCP | 18443 | 192.168.62.10 | 443 | `https://服务端公网IP:18443` |

地址只是示例，应填写客户端实际可达的目标。目标端口必须已有服务监听；映射不会自动打开目标设备的管理功能。HTTP/HTTPS 取决于目标服务，TLS 证书检查仍由访问端执行，路由器后台仍需登录。

目标看到的是客户端路由器发起的代理连接，不保留访客原来的 IP。目标侧的 IP 白名单会按代理来源判断，不能据此限制原访问者；尤其不要依赖回环目标的后台来源限制。请在本功能的“允许访问的来源网段”中填写准许访问者的公网 IPv4/CIDR。

1. 在服务端进入“VPN设置 → VPN客户端 → WireGuard”，编辑“隧道列表”中的客户端设备，连接方式选择“纯 Hysteria 2（UDP）”，启用“反向端口映射”。
2. 填写 TCP/UDP、服务端映射端口、客户端目标 IPv4/端口，以及允许访问的来源网段。来源必须使用 IPv4 CIDR，单个访问者填写其公网 IPv4 加 `/32`；每条映射至少填写一个来源。`0.0.0.0/0` 明确表示允许所有 IPv4 来源，多个来源用逗号分隔。
3. 点击“保存”后点“复制到路由器”，到客户端爱快依次点“粘贴导入配置”→“预览路由器配置”。核对目标和来源限制后点“确认导入”。启用反向功能的路由器配置使用 v2 格式；普通手机 JSON 和 HY2 分享链接不含反向凭据。更新已有配置时须先删除客户端旧的导入隧道，再导入新包，保留服务端设备；具体影响见下文“修改、停用与恢复”。
4. 服务端所在云平台或上级防火墙应放行所选映射端口及协议。现有 HY2 的 UDP 入口仍需可达。客户端只需能够主动连接服务端 HY2。
5. 在服务端重新打开该设备编辑页，在客户端打开已导入隧道，两端各点“读取连接状态”，并从允许的来源实际访问目标。访问时使用“服务端公网 IP + 映射端口”。

映射的是具体服务，不会自动让服务端公网 IP 代表客户端所有端口，也不会建立完整的双向网段路由。需要哪个服务，就配置对应的映射。每台设备最多 32 条映射，每条最多 16 个来源网段；当前映射端点使用 IPv4。

## 怎样判断已经可用

配置已保存、HY2 本地进程运行、反向通道已连接以及目标服务实际可用是不同状态。页面通过“读取连接状态”显示一次快照，没有自动轮询。

| 状态 | 能说明什么 |
| --- | --- |
| 普通 HY2 运行中 | 本地核心和所需接口运行；不能单独证明反向连接成功 |
| 反向通道 · 已认证连接 | 两端已通过凭据及映射摘要校验，心跳有效 |
| 服务端端口监听 · 已监听 | 这条映射的服务端端口已成功绑定 |
| 最近目标连接成功 | 已有请求到达客户端目标并获得目标侧连接或响应证据；具体含义受 TCP/UDP 影响 |
| 目标不可达 / 连接失败 | 反向通道可能仍在线，应检查客户端目标地址、监听端口和防火墙 |
| 无记录 | 尚无对应证据，不能当成零延迟或成功 |

最后应以实际网页、应用或协议请求成功为准。TCP 目标建立连接不能证明后台登录或整个应用工作正常；UDP 要看目标的实际响应。尚未访问过的映射可以显示通道在线，但没有目标成功记录。

## 修改、停用与恢复

- 修改前须确保可以通过客户端局域网或其他独立管理入口操作客户端。服务端保存新映射会撤销旧反向凭据，不能仅依赖即将撤销的映射通道给客户端更新配置。
- 修改映射的协议、端口、目标或来源列表会轮换该设备的反向凭据。保存后须重新导出并在客户端更新路由器配置，旧包不能继续建立反向会话。
- 当前导入入口不会覆盖已导入的同一 HY2 身份。更新时先在客户端删除原来的导入隧道，再粘贴新包；不要在服务端删除设备。删除至重新导入之间，该客户端的普通 HY2 连接也会暂时中断，依赖此隧道的出口规则需在更新后核对。
- 不改映射而保存其他设备信息时保留有效反向凭据。关闭后再开启会生成新凭据。
- 客户端自动重连。会话断开或心跳失效后，服务端撤销该会话的映射监听；重新认证成功后再绑定。
- 多条映射采用整组绑定：其中一个端口不能绑定时，该设备的本组反向监听不会部分启用。普通 HY2 上网仍可独立运行，页面会显示反向错误。
- 删除、停用或更换设备配置会撤销相应反向进程和规则。只读状态查询不会启动服务。
- 未启用反向功能的普通路由器配置仍使用 v1，现有 v1 导入保持兼容。

## 实现与边界

固件内置 `nr-hy2-reverse`，每台设备拥有独立配置和进程。客户端的控制连接与工作连接统一通过该设备独立的本机 SOCKS 入站进入 HY2，无直连回退。HY2 提供加密传输；反向层负责设备认证、会话和端口映射，不自行实现新的加密协议。

服务端控制入口仅放行该设备对应的私有网关 TCP 端口，公开监听由设备反向会话控制。客户端连接目标时使用既有原生本机路由标记，避免目标访问再次被分流送入同一隧道。来源限制在实际监听处再次核对。

UDP 按来源维护有界会话，并在反向工作连接中保留数据报边界。该版本的反向工作连接使用 TCP，UDP 业务会受到其重传和队头阻塞影响；功能测试不能推导高吞吐、低延迟或游戏性能。每个设备最多同时保留 64 个工作会话，其中 UDP 会话最多 32 个，空闲 UDP 会话会过期。
